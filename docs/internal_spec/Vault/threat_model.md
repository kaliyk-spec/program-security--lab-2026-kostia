# Модель загроз (Threat Model) модуля Vault

Аналіз загроз виконано за методологією **STRIDE**:

| Загроза (STRIDE) | Сценарій ризику | Контрзахід у бізнес-логіці / архітектурі |
|---|---|---|
| **Spoofing** | Підміна ідентичності клієнта під час запиту. | Ізоляція модуля автентифікації (`Identity`); Vault оперує перевіреними контекстами доступу. |
| **Tampering** | Модифікація зашифрованих даних у БД. | Використання режиму AES-GCM (перевірка автентичності через Authentication Tag). |
| **Repudiation** | Відмова від факту перегляду або відкликання секрету. | Обов'язкове збереження незмінного запису `AuditLog` при кожній операції через доменний сервіс. |
| **Information Disclosure** | Витік секрету через логи, помилки або доменні івенти. | Доменні івенти містять лише ID та дати; пейлоад інкапсульовано у `EncryptedDataVO`. |
| **Elevation of Privilege** | Спроба читання відкликаного чи простроченого секрету. | Примусова перевірка стану через `AccessSecretDPolicy` перед викликом дешифрування. |
